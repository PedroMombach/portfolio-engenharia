# Curve Extractor MK2

[Português](README.md) | **English**

Pump, fan and head-loss curves almost always arrive as charts: a catalogue PDF
or a scanned image. To use that data in a calculation, someone has to read it
off the screen point by point and type it in. This application does the
reading. You calibrate the axes, click along the curve, and get the points in
engineering units, ready for CSV or Excel.

![MK2 interface with three example curves](docs/images/v2-preview.png)

![Execution: Open PDF, calibrate, click curve, export](docs/images/demo.gif)

## Download and use (Windows)

No Python installation needed.

1. Download `ExtratorDeCurvasMK2-v1.0.0-windows-x64.zip` from the repository's
   [Releases](https://github.com/PedroMombach/portfolio-engenharia/releases)
   page.
2. Extract the whole folder to a location where you can write files.
3. Open `ExtratorDeCurvasMK2.exe`.

Keep the `_internal/` folder next to the executable. Preferences and logs are
stored beside it. The `.sha256` file on the release lets you check the download.
The interface is in Portuguese; menu names below are shown as they appear.

## From image to table in four steps

To try it, use the [synthetic catalogue](docs/exemplo/catalogo-sintetico.pdf), with a
fictitious brand and values. Page 1 imitates a slightly skewed scan with head,
efficiency and NPSH curves. Page 2 has a log-log chart. The file is generated by
`tools/gerar_catalogo_sintetico.py`.

**1. Open the document.** Use **Abrir documento** (Open document), drag the
file onto the canvas or paste with `Ctrl+V`. For multi-page PDFs, pick pages
from the thumbnails.

![Interface: Selecting PDF pages](docs/images/passo1-abrir.png)

**2. Calibrate the axes.** Click **Criar curva** (New curve) and mark three
points of known value. Three-point affine calibration absorbs scan rotation and
skew. Axes can be linear or logarithmic.

![Three points marked on a slightly rotated graph.](docs/images/passo2-calibrar.png)

**3. Capture the curve.** Click along the curve. The magnifier, zoom and undo
(`Ctrl+Z`) help with precision. For more curves on the same chart, use
**Duplicar calibração anterior** (Duplicate previous calibration).

![Curve being captured by clicking, with the magnifier open](docs/images/passo3-capturar.png)

**4. Export.** Choose the curves, the common X base, the interpolation (linear
or PCHIP) and the format (CSV or XLSX). The `SeletorBombasMK3` profile writes
`Q,H,Eta1,NPSH` columns, the same format used by
[Pump curves](../curvas-bombas/README.en.md).

![Interface: export dialog next to the resulting spreadsheet](docs/images/passo4-exportar.png)

Work can be saved as an `.ecp` project with the images embedded, and reopened
without the original PDF. Shortcuts, theme, colours and DPI are configurable
under **Preferências** (Preferences).

## What sets it apart

- **Skewed axes:** three-point calibration, no need to straighten the image.
- **Logarithmic axes:** handled directly, with no manual conversion.
- **Several curves per chart:** each curve has its own calibration. On export,
  all of them are interpolated onto a common X base.
- **Output in the consumer's format:** export profiles remove a conversion
  step.

## Accuracy

The automated tests use synthetic charts of known geometry: aligned axes, axes
rotated by 3°, logarithmic axes, and axes that do not meet at the origin. In
every case the required error is below **0.5 % of full scale**.

In practice, pointing error (stroke width, cursor position) outweighs
calibration error. The application does not validate quantities or units: axis
values are entered by the user.

## Background

[Engauge Digitizer](https://github.com/akhuettel/engauge-digitizer), by Mark
Mitchell, is very complete, but its interface did not fit the way my colleagues
and I work. That led to a first Tkinter version: rough, but functional.

![First version, built with Tkinter](docs/images/v1-tkinter.png)

The improvement list for a second version sat idle for a long time. With the
help of **coding agents**, it became this application: a new interface, a
complete workflow and automated tests. The code was written from scratch and
shares nothing with Engauge. I mention it because the way it was built is part
of what the project demonstrates.

## Running from source

Requires [Anaconda](https://www.anaconda.com/download) or [Miniconda](https://docs.conda.io/projects/miniconda/). Open **Anaconda Prompt** from the Start menu, go to
this folder (`cd /d "path\to\this\folder"`) and run the commands below. The
first one is only needed the first time:

```bat
conda env create -f environment.yml
conda activate extrator-de-curvas
python -m curveextractor
```

To run the tests: `python -m pytest`.

To build the portable package:

```bat
pip install pyinstaller==6.22.3
python tools\build_release.py
```

The package is written to `release/`, which is kept out of the repository.

The calculation core (`src/curveextractor/core/`) does not depend on the GUI.
